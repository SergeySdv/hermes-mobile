# Hermes Mobile + Rokid — план агентской реализации

Версия плана: 1.1 (ADR на review) · 28 октября 2026 · язык: русский.
Статус: **спецификация и задания, не реализованный продукт**. Ни один технический gate ещё не пройден.

## Результат, который нужно получить

Общий APK Hermes Mobile для пользователей с очками и без них. Поддержка Rokid — необязательное отдельно устанавливаемое Android-дополнение; на очках — companion APK. В основном клиенте допускается только небольшой универсальный IPC-интерфейс расширений, без Rokid SDK и протокола. Агент, инструменты и окружение остаются в существующем изолированном контейнере VPS. Telegram сохраняет работоспособность.

Фото, сделанное очками, попадает в выбранный разговор телефона. Быстрый локальный OCR/перевод не ждёт агентного цикла. Ответ Hermes постепенно отображается на очках и полностью сохраняется в чате. После обрыва связи приложение восстанавливает состояние, а не молча повторяет поручение.

## Важное уточнение первоначальной идеи

Не строить «Hermes Mobile → Dashboard, очки → отдельный OpenAI endpoint» и не пытаться склеить эти диалоги одинаковой строкой session ID. Основной путь — существующий chat pipeline Hermes (G0: orchestration в ChatViewModel, repository отвечает за persistence) и один проверенный серверный транспорт для телефона и очков. API-адаптер допустим только как согласованная альтернатива для целого разговора. Основание и границы проверки: [источники](SOURCES.md), [архитектура](specs/01-ARCHITECTURE.md).

## Как передать агенту

1. Скопировать каталог в рабочее дерево форка, например `docs/rokid-plan/`. Не заменять корневой upstream `AGENTS.md` этим файлом.
2. Дать агенту [START_HERE.md](START_HERE.md), затем [AGENTS.md](AGENTS.md).
3. Начать только с [T00](tasks/T00-BASELINE.md). Выполнять по одному заданию; на границе gate — отчёт и проверка допуска.
4. Прочитать [ADR-003](adr/ADR-003-OPTIONAL-ANDROID-ADDON.md): PROPOSED, реализация до review и gates запрещена. G0 BLOCKED зафиксирован в [отчёте](reports/G0-baseline.md); [STATUS](STATUS.md) указывает на актуальный BLOCKED; review ожидается.

До принятия ADR разрешено только документирование. После review независимые моки и компоненты требуют допуска соответствующего task; отсутствие очков/VPS не даёт hardware PASS. Соответствующие интеграционные gates остаются `BLOCKED`/`NOT_RUN`. Отсутствие оборудования не является поводом выдумывать успешные проверки.

## Порядок работ

Rokid: `G0 → {G1 hardware, G2 backend} → G3 vertical slice → G4 sessions → G5 streaming → G6 OCR → G7 resilience → G8 release`. Обычный Hermes выпускается независимо по H-RELEASE; G8 использует уже проверенную версию Hermes. H-RELEASE пока NOT_RUN.

`G9 voice/video` — независимая следующая фаза, не условие выпуска текстово-фотографического MVP.

Предлагаемые численные критерии в документах — целевые требования реализации, не измеренные характеристики устройств. Их нельзя тихо ослаблять ради зелёного отчёта.
