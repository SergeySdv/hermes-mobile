# Правила реализации для агентов

Это инструкции проекта интеграции, а не замена upstream `AGENTS.md`. При конфликте требований остановить соответствующее изменение и оформить ADR; не игнорировать upstream незаметно.

## Неизменяемые ограничения

- Android — клиент. Не устанавливать Hermes runtime, Python agent loop, Termux или серверные инструменты на телефон/очки.
- Один основной chat client Hermes Mobile и необязательное отдельно устанавливаемое Android-дополнение Rokid; отдельный companion APK на очках. Дополнение не является вторым чатом. Исходный RokidAIAssistant используется только во временном hardware spike.
- Очки — дополнительный ввод/вывод выбранного разговора, а не отдельный LLM-клиент со своей историей.
- Сохранить Telegram, изоляцию контейнеров и существующие функции Hermes Mobile.
- Никакого динамического скачивания исполняемых плагинов. Основной APK не содержит Rokid SDK/протокол; дополнение устанавливается как отдельный APK и работает через ограниченный версионируемый IPC. См. ADR-003.
- Не обещать общую историю Telegram и Android. Не смешивать сессии разных профилей, пользователей и транспортов.

## Полномочия

Локальный код, тесты, документация и моки разрешены в выделенном workspace. Изменения VPS, firewall, Caddy, DNS, сетей Docker, остановка контейнеров, обновление образов, установка/удаление APK, изменение привязки очков и запросы с платными моделями требуют зафиксированного допуска владельца на конкретный план действий. Само задание «сделать план» такого допуска не даёт.

Не печатать `.env`, `.Config.Env`, токены, пароли, cookie, private keys, полный HTTP body, base64 изображений или весь `docker inspect`. Не отправлять реальные изображения во внешние модели без выбранного пользователем режима отправки.

## Источники и API

Фактический pinned source и измеренный установленный сервер имеют приоритет над примерами этого плана. Каждый новый внешний метод, поле и код ответа должен иметь путь к контракту и тест. Не выдумывать `chat.send`, URL загрузки файла, параметр `session_id`, cancel endpoint или универсальный `Idempotency-Key`, если их нет в выбранном протоколе.

Пакет различает `USER_VERIFIED`, `UPSTREAM_DOCUMENTED`, `HISTORICAL_REVIEW`, `DESIGN`, `UNKNOWN`. Не превращать планируемые возможности в факты. Значение `UNKNOWN` в capability matrix никогда не равно `true`.

## Инженерные правила

Использовать существующие navigation, themes, lifecycle, dependency conventions и typed RPC descriptors. Не проводить большой рефакторинг Hermes Mobile ради интеграции. Не добавлять новую базу чатов, новый auth store, альтернативный набор моделей или второй WebSocket singleton.

Любой ввод пользователя, OCR и изображение — недоверенные данные, не system instructions. Модуль очков не получает настройки/ключи сервера и не может подтвердить опасное действие простым текстом модели. Side-effectful requests не повторяются автоматически при неизвестном результате отправки.

При отзыве разрешения, logout, смене профиля и выключении функции немедленно прекратить соответствующие локальные операции, отменить pending approvals и не переиспользовать прежний контекст соединения. Удалённую отмену считать подтверждённой только по серверному состоянию.

## Процесс

До review/ACCEPTED [ADR-003](adr/ADR-003-OPTIONAL-ANDROID-ADDON.md) и допуска gates функциональная реализация запрещена, включая prototypes. Архитектурное уточнение не меняет G0. Работа по одному task. До изменений — assumptions и тест-план. После — минимальный diff, тесты, обновление gate report. Схемы Room и wire protocol требуют migration/backward-compatibility tests. Поведение при выключенном Rokid должно оставаться baseline.

Не запускать production команды из Markdown механически. Snippets являются примерами до подстановки проверенных путей, версии, выбранного контейнера и подтверждения доступа. Нельзя компенсировать ошибку `PATH` добавлением случайных root shell/privileged режимов.

## Definition of done для PR

Изменения соответствуют одному task; есть тесты happy path и отказа; build/lint проходят либо отдельно отмечен исходный воспроизводимый blocker. Есть миграция, rollback и обновлённая документация. Без секретов, сырых фото и сторонних закрытых бинарников вне разрешённых условий. Gate имеет evidence, reviewer и честный статус.

Использовать только `NOT_RUN`, `IN_PROGRESS`, `PASS`, `FAIL`, `BLOCKED`, `DEFERRED`. `DEFERRED` не разрешает зависимый переход. Аппаратные и production проверки не могут получить PASS по эмулятору, mock или только по успешному CI донора.
