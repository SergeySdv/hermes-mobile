# 05. Companion для Rokid и аппаратный протокол

Исходная база — `glasses-app` и hardware части donor. Наличие кода не подтверждает поддержку конкретной китайской прошивки. Исторический обзор и источники — [S05, S08, S09](../SOURCES.md).

## Аппаратный preflight

Владелец фиксирует точную модель, firmware, Android API, официальный app/version и способ установки APK. Никаких инструкций по root/разблокировке без отдельной задачи; при штатном запрете установки — BLOCKED, а не попытка обхода.

Read-only ADB примеры после подключения обоих устройств и выбора serial:

```bash
adb devices -l
adb -s "$GLASSES_SERIAL" shell getprop ro.product.model
adb -s "$GLASSES_SERIAL" shell getprop ro.build.version.release
adb -s "$GLASSES_SERIAL" shell getprop ro.build.version.sdk
adb -s "$GLASSES_SERIAL" shell getprop ro.build.display.id
```

Serial хранится только локально. Не использовать `adb install` без `-s` при нескольких устройствах; не сбрасывать глобальный ADB server и не стирать logcat других задач. Установку согласовать отдельно. При конфликте подписи не удалять исходное приложение и его данные для «быстрого исправления».

Перед тестом записать штатный pairing/camera/display behavior. После завершения восстановить его и проверить, что официальное приложение работает. Конкуренция двух приложений за camera/SPP — тестируемая совместимость, не повод автоматически force-stop всего телефона.

## Что оставить на очках

Camera2 capture, безопасная обработка кнопки/тапа, transport client, дисплей, настройки шрифта/области и page navigation. Отдельно — состояние battery/thermal, если OEM API его предоставляет. Нет cloud keys, собственного Hermes или долговременной истории чата.

Сначала donor APK без логических изменений: установить, увидеть текст, снять/получить JPEG. Затем переносить минимальный набор. Каждая миграция package ID, manifest authority, intent action или CXR integration проверяется: hardcoded package references могут мешать.

## Camera state

`Unavailable → Idle → Preparing → Capturing → Encoding → Transferring → Idle` плюс error/cancel. Вход через явное действие пользователя. Одновременно один capture; повтор команды с тем же ID возвращает прежний результат/статус, не запускает второй снимок.

Закрывать `Image`, reader/session/camera и worker thread на всех terminal paths. Timeout подготовки, съемки и передачи различать. Не проглатывать ошибку camera permission или camera busy. После cancellation текущего кадра освободить ресурсы; повторный запуск возможен только новой явной командой.

Не включать постоянный preview/capture loop ради улучшения задержки до измерений. Оптимизация повторного открытия камеры — отдельный PR с battery/thermal regression. Исторически найденные задержки donor требуют перепроверки выбранного SHA, не копируются как гарантированный FPS.

## Качество изображения

Для надписей выбрать измеренный профиль still photo. Не наследовать 640×480 «видео» как единственный размер OCR. Сохранить достаточную резкость текста, EXIF orientation и возможность crop. Допустимы быстрый preview на телефоне и отдельный основной кадр, но их нельзя считать одним и тем же изображением в history без явной связи.

Контролировать encoded size и decoded pixel count. GPS/лишние EXIF удалить до cloud upload; timestamp и orientation хранить структурированно. Не уменьшать качество автоматически так, что изображение становится непригодным, без visible warning. На плохом кадре предложить переснять.

## Дисплей и incremental rendering

Дисплей получает нормализованный plain text, режим, stream ID и revision. Не рисовать Markdown source/сырые tool arguments. Преобразование Markdown в текст не должно удалять полезные числа, названия и ссылки целиком; длинные URL оставить на телефоне.

Режимы: `STATUS`, `TRANSLATION`, `AGENT_ANSWER`, `ERROR`. Приоритет: critical connection/error → пользовательский выбранный режим → обычный progress. Перевод не прыгает в длинную энциклопедическую справку автоматически. Полный ответ всегда остаётся в телефоне.

Первый рабочий streaming вариант — throttled snapshots каждые 250–500 мс при изменениях; terminal отправляется немедленно. Это настраиваемый проектный интервал, не измеренный hardware предел. Не посылать пакет на каждый токен.

Page anchor привязан к видимому содержимому, не просто к индексу массива страниц. Обновление хвоста не сбрасывает страницу; ручная навигация выключает auto-follow до явного «к последнему». Не разрезать UTF-8, surrogate pairs и grapheme clusters. Проверить кириллицу, китайские знаки, emoji и длинные числа на реальном шрифте.

Большой ответ имеет ограничение представления на очках и понятное «полностью — на телефоне»; канонический текст не обрезается в базе. Старый stream не возвращается на экран после нового вопроса. Clear/display-off — локальная явная команда без удаления истории.

## Reconnect и доставка

Поддерживать separate counters: команда поставлена в очередь, отправлена, получена устройством, применена UI. ACK транспорта не доказывает читаемость текста человеком. Для hardware gate нужна визуальная проверка; для latency — callback применения frame, честно помеченный как proxy measure.

После reconnect повторять только current settings и latest relevant display snapshot. Не повторять capture/agent submission. Незавершённый transfer либо безопасно возобновляется по подтверждённому offset/hash, либо завершается ошибкой и запрашивает явное действие. Не возобновлять его в другом профиле/разговоре.

## Совместимость версий

В релизной матрице фиксировать phone APK, companion APK, protocol version и проверенный firmware. Новая команда — capability-gated. Несовместимая major version отключает функцию с инструкцией обновления. Старый companion может поддерживаться в final-only режиме только если это реально протестировано; не считать его автоматически совместимым.

## Обязательные аппаратные проверки

Текст/страницы/кириллица; 10 still photos; отказ permission; занятая камера; отключение во время chunks; потерянный ACK; repeated button; перезапуск companion; reconnect после ухода из зоны; выключенный экран телефона; normal operation официального приложения после остановки нашего. Результат заносится в hardware report с версиями и sanitized evidence.
